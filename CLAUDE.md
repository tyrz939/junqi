# The Bell at Nine (repo `Junqi`, crates `jane-*`): agent guide

Only agents work in this repo. The owner (John) directs and play-tests; he does not read code. Read this file first, then only the docs your task needs (the map below). `AGENTS.md` points here for tools that look for that name.

## What it is

A pixel-art action RPG in Rust: one hand-tuned, seeded county; integer-only; deterministic lockstep (LAN co-op for 1–4). All art and audio are generated by code. It targets PC (soft/gl2/wgpu backends) and a real PSP-1000 (`spikes/psp-game`). The old TypeScript build in `jane/` is frozen: never edit, run or keep it in step.

## Hard rules (a change that breaks one is wrong, whatever else it fixes)

1. **The sim is deterministic and float-free.** `jane-core`, `-schema`, `-data`, `-world`, `-sim`, `-net`, `-bot` and `-art` never name `f32`/`f64` (`tools/ci/float-gate.sh`). Nothing on the sim's state path reads the clock or walks a `HashMap`. The PSP may look slightly different from the PC; it must simulate identically.
2. **Content is data.** Tables live in `data/*.json`, compiled by `jane-schema` into `jane-data` statics at build time. Nothing parses JSON at runtime. A new cart, lever or foe is a row, not code.
3. **Nothing is "built" until a test names it.** Docs mark what is built and what is only proposed. If you build something, update the doc's status line in the same commit.
4. **Docs are the contract.** `PORT.md` and `ARCHITECTURE.md` are the build's agreement, and `PLAN.md` is the game's. If code drifts from them, fix one of the two in the same change.
5. **Fixtures move only on purpose.** `tests/fixtures/hashes-x86_64.txt` (worldgen) and `bot-hash-x86_64.txt` (the bot replay) change only when you mean to change the world or the sim. Say so in the commit message.
6. **No hacks on the PSP.** User-mode only: no kernel mode and no custom Media Engine code. Firmware services (SAS, audio channels) and the VFPU are fine. A change to the look needs a side-by-side A/B for the owner first.

## Gates (run before every commit that touches code)

```bash
export CARGO_BUILD_JOBS=6
cargo fmt --all --check
cargo clippy --workspace --all-targets --exclude jane-render-wgpu -- -D warnings
cargo test --release --workspace --exclude jane-render-wgpu        # >10 min: run it in the background
bash tools/ci/float-gate.sh
cargo run -q --release -p jane-cli -- play --fixture tests/fixtures/bot-hash-x86_64.txt
git checkout tests/fixtures/bot-hash-x86_64.txt                   # the replay rewrites only its line endings
bash tools/psp-dist.sh                                             # when anything the PSP links changed
```

- Slow tier, before a merge that touches the sim, worldgen or bots: `cargo test --release --workspace -- --ignored --skip full_` (about 7 min).
- During work, test the crate you touched first, then run the full gates: `cargo test --release -p jane-sim --test <name>`.
- `spikes/psp-game` is outside the workspace. Format it with `cargo +1.94.1 fmt`, then `git checkout` the unrelated files that touches (`ahead.rs`, `loader.rs`, `micro.rs`, `perf.rs`).
- Run clippy workspace-wide as in the gates. `-p <crate>` alone builds a different feature mix and can fail on lints the gate doesn't see (for example `jane-sim/src/baked.rs`).
- Clippy and tests don't cover psp-game. `tools/psp-dist.sh` builds it, and the PSP bench (below) is its test.

## The PSP loop

- **Build:** `bash tools/psp-dist.sh` writes `dist/TheBellAtNine-PSP-<commit>.zip`. The owner copies it to a PSP-1000 (333 MHz, 16 KB D-cache).
- **Hardware runs:** the owner runs Benchmark and sends back `dist/JANE00001/`: `bench.txt`, `crash.txt` and `capture-*.bin`.
  - Archive each run in `progress/YYYY-MM-DD_NN_hw-bench/`.
  - Compare runs with `cargo jane bench report BASE NEW --profiles --out DIR`.
- **Emulator bench** (PPSSPP headless; it does not model the cache or the GE, so hardware is 3–4.6× slower and sim about 10× slower):

  `PPSSPP_PSP1000=1 PPSSPPHeadless.exe <prx> --root=<dir> --memstick=<dir>/memstick -j --timeout=2400`

  Set it up in a scratch folder: copy the county and pack files and the prx from `spikes/psp-game/target/mipsel-sony-psp/release/psp-game.prx`, plus a `script.txt` containing `bench`.
- **Threads** (a lower number runs first): audio 16, loader 30, game 32, painter 48 (boosted to 31 when the view shows unpainted swatches).

## Working conventions

- **Branch and push:** work on `density-integration` (or a worktree branched from it). After a verified commit, push it and fast-forward `main`: `git push origin density-integration && git push origin density-integration:main`. Remove a worktree and its branch once it's merged.
- **Commit messages** say what changed in the game's terms, in plain sentences.
- **Screenshots:** keep milestone shots and bench runs in `progress/`.
- **Reports to the owner** are short and plain, with numbers before and after. He decides the big calls and any change to the look.
- **Big files:** `jane-present/src/present/draw.rs` (`draw()` alone is about 940 lines), `jane-render-psp/src/list.rs` (3.7k) and `spikes/psp-game/src/main.rs` (3.2k). Read them by section (grep for `fn `), not whole.
- **`spikes/psp-game/vendor/`** is the vendored `psp` crate. Don't edit it, and leave it out of searches.
